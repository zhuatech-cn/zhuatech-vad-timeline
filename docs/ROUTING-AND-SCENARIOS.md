知华科技（上海如静知华信息科技有限公司）· https://www.zhuatech.cn/

## 日常岗位流转

业务员提交后默认进入待复核状态；同一账号不能复核自己提交的单。复核员和管理员可以打开「复核队列」，按标题筛选，点「办理分派」。公共待领排除本人提交的记录。我负责的只列本人在办；团队视图可见本企业待复核记录。已办或已撤回的批次自动退出队列，历史仍可从详情查看。

- **领取**：空闲记录归自己，不能抢占其他人正在处理的记录。
- **派单**：管理员按本企业有效复核员/管理员的账号分派；接收人不能是提交人。
- **交接、释放**：当前负责人或管理员填写原因。接收人停用或转岗时，旧会话失效，管理员在“负责人已停用或转岗”范围重新派单。
- **独立复核**：未分派的批次保留直接独立审批流程。已分派后，即使是管理员也不能代替现负责人审批；先办理交接。业务员仍可以撤回自己的待复核批次。

## HTTP API（同源 /api，Bearer 认证）

| 方法 | 地址 | 请求及返回 |
|---|---|---|
| GET | `/review-queue?scope=OPEN&q=&page=1` | 范围 OPEN / MINE / TEAM / STALE；每页 20 条，最早提交在前。 |
| GET | `/runs/{id}/routing?before=0` | 当前负责人、分派版本、最近 20 条交接。用返回的 nextBefore 继续向前读，0 表示结束。 |
| POST | `/runs/{id}/routing` | 必须有 Idempotency-Key（8–80 位字母、数字、下划线或短横线）。JSON 例：`{"expectedVersion":0,"action":"CLAIM","target":"","note":"早班领取"}`。ASSIGN 和 HANDOFF 须填接收账号；除 CLAIM 外均须写原因。相同键和内容重发返回原回执，不重复记账；版本过期或同键内容不一致返回 409。 |
| POST | `/runs/{id}/scenarios/preview` | 业务员、复核员或管理员提供 `expectedRevision` 和 1–3 个 `{name,settings}`。参数完整，名称及方案不重复，须区别于原始设置；整组没有成功就不交付部分结果。 |

**两个版本号不能混用。** 分派使用 route_version（旧单从 0 开始）；分析批次使用 revision（供修订、复核及证据导出）。分派事件写入独立的追加记录并进入管理员审计；不是分析证据 ZIP 的一部分。已分派并不表示数学门槛达标，原有例外审批规则依然生效。

## 值班翻页与离线评审

「等待时间」从批次首次提交起算，不是领取或交接后的时长。队列标明本机时区和本次查询时间；改变筛选可纳入新单。在当前范围，下一页按上一页最后一条记录定位，不会因为前一页已领走或已办结就跳过未看记录。办理状态实时变化，队列不是历史快照。

接口参数 `minWaitMinutes` 为 0–10080 的整数。首次不传 `cursor`；看下一页时保持账号、范围、关键词和时长不变，传响应中的 `nextCursor`（空字符串表示结束）。可用 `firstCursor` 返回同一提交截止时间的第一页。定位超过 15 分钟返回 409，重新筛选即可。旧客户端的 `page` 参数仍可用，但不保证队列变化时偏移稳定。

下载同一版本的正式证据 ZIP 及试算 JSON，用下面命令生成单文件评审页。要求 Python 3.9+，只用标准库，无需联网。证据摘要应从独立可信记录获取；可用 `--scenario-sha256` 进一步核对试算文件。工具核对项目、版本、输入与原结果的精确 SHA-256 和数学差值；不代表签字或重新运行模型。旧版试算 JSON 缺少来源摘要，需要在新版本重新导出。

```bash
python3 scripts/render_scenario.py --evidence evidence.zip --evidence-sha256 TRUSTED_SHA256 --scenario preview.json --out review.html
```

英文加 `--lang en`，默认不含样本明细、账号、审批备注或原参数。方案名称和批次编号仍可能涉及业务隐私，发送前请复核。

## 实际试一次

1. 使用 `examples/acceptance.json` 建立原单。先用复核员领取，再按账号交给另一位复核员，查看时间、前后负责人和办理原因。
2. 打开「业务参数试算」，点「载入参数示例」再运行。样本为项目验收数据时，方案「忽略不足 101 毫秒的片段」的 `ignored` 应为 3（绝对容差 1e-10）。
3. 「归档值」来自原单；「原参重算」和「方案值」在同一版本算法、同一批行上计算。差值为方案值减去原参重算值；缺失不按零处理。试算不套用门槛、不触发审批、不调用云服务。下载的 JSON 标记 previewOnly，不是正式的验收证据。

## MySQL 时区

外部 MySQL 的 JDBC URL 建议使用 `connectionTimeZone=%2B00:00&forceConnectionTimeZoneToSession=true`（Compose 示例已经配置）。这会让本应用使用 UTC 会话，不修改数据库全局时区，也不依赖服务端额外安装命名时区表。浏览器再转换为使用者的本地时间。不要只改服务器全局时区来修补显示问题。参见 [Connector/J 时间处理说明](https://dev.mysql.com/doc/connector-j/en/connector-j-connp-props-datetime-types-processing.html)。
